# Fastango — Code Review & Improvement Notes
*Date: 2026-05-27*

The bones are solid — clean layering, security-first defaults, good auto-discovery. Notes below are scoped to issues, gaps, and high-value additions.

---

## 🔴 Critical bugs (should fix soon)

### 1. Custom exceptions are never handled
[app/core/exceptions.py](../app/core/exceptions.py) defines a `FastangoException` hierarchy (`NotFoundException`, `UnauthorizedException`, etc.) but [app/exceptions.py:22](../app/exceptions.py#L22) only registers a handler for bare `Exception`. If any service raises `NotFoundException`, it falls through to the 500 catch-all.

Wire handlers for each, plus `HTTPException` and `RequestValidationError`, so every response uses the `{error, message, data}` envelope.

### 2. `local.env` is committed with a literal `SECRET_KEY`
[local.env:13](../local.env#L13) ships `SECRET_KEY=super-secret-dev-key-change-in-production...`. Rename to `.env.example`, gitignore the real `.env`, and have `Settings` load `.env`. Right now anyone cloning runs with a known signing key by default.

### 3. Dev-mode auth bypass leaks too widely
[app/core/security.py:111](../app/core/security.py#L111) returns a hardcoded UUID when no Bearer token is sent *and* `APP_ENV in ("local","test","testing")`. One env misconfig in staging (`APP_ENV=local`) and every protected route becomes public.

Better: restrict to `APP_ENV == "test"` only, and use `app.dependency_overrides[get_current_user_code]` in [tests/conftest.py](../tests/conftest.py) instead.

### 4. Double commit / nested transaction confusion — ✅ FIXED
*Resolved: `get_db()` no longer auto-commits; services own transactions via `async with db.begin():`, and an uncommitted-write guard in `app/database.py` fails requests that end with pending writes.*
[app/database.py:55-63](../app/database.py#L55-L63) commits at end of request, but [app/modules/auth/services.py:33](../app/modules/auth/services.py#L33) opens `async with db.begin():` inside the same session. With `autoflush=False` and no explicit savepoint config, this is fragile. Pick one strategy — usually services own transactions, and `get_db()` only rolls back on exception (no auto-commit).

### 5. Dead dependencies
[pyproject.toml:19-20](../pyproject.toml#L19-L20) lists `python-jose` and `passlib`, but you use `PyJWT` and `bcrypt` directly. Drop them — they're large transitive trees with their own CVE history.

### 6. `inject_db_session_context` runs on **every** route
[app/main.py:51](../app/main.py#L51) makes it a global app dependency, so `/health` opens a DB connection on every probe. Move it to the API router in [app/core/registry.py:92](../app/core/registry.py#L92) instead.

## 🟡 Security gaps

- **No `RequestValidationError` handler** → 422s leak Pydantic's verbose error shape, not the envelope.
- **JWT missing `jti`, `iss`, `aud`** — without `jti` you can't revoke individual tokens.
- **No token blacklist / Redis denylist** — once issued, can't invalidate on logout or compromise.
- **Rate limiter is in-memory** ([app/core/rate_limit.py:15](../app/core/rate_limit.py#L15)) — per worker only. Use `storage_uri=settings.REDIS_URL`.
- **Rate limit by IP only** — behind a proxy/NAT everyone shares the bucket. Add a per-user limiter for authenticated routes.
- **No CSRF protection** — fine for pure JWT-in-header APIs, but if you ever add cookie auth, document this.
- **CORS allows credentials with explicit origins** — good. But `allow_methods` includes `DELETE` and `PATCH`; consider whether the front-end actually needs them.
- **Password policy is weak** — only `min_length=8`. No uppercase/digit/symbol check, no breach-list check (haveibeenpwned API).

## 🚀 High-value features to add

1. **`fastango` CLI** (biggest Django-parity win): `fastango startapp orders` scaffolds `apps.py / models.py / schemas.py / repositories.py / services.py / router.py / constants.py` with proper imports. This is the single feature that would make Fastango feel like Django.
2. **Permission/policy framework** — decorator like `@require_permission("admin:write")` reading from a `Permission` table or JWT claim. README promises DRM.
3. **Pagination helper** (`Paginated[T]` generic, `?page=&page_size=`) and **filter helper** (`?filter[email]=...`).
4. **Background task layer** — `arq` or `TaskIQ` (async-native Celery alternatives). Wire to Redis already provisioned.
5. **Cache decorator** (`@cache_query(ttl=60)`) using Redis — repos are perfect targets.
6. **Request ID middleware** — generate UUID, propagate in `X-Request-ID`, attach to logs.
7. **Structured logging** (JSON via `structlog`) — wins in production log search.
8. **Deep health check** — current `/health` always returns ok. Add `/health/ready` that pings DB + Redis.
9. **`/metrics` endpoint** via `prometheus-fastapi-instrumentator`.
10. **File upload demo** that actually uses [app/core/storage.py](../app/core/storage.py) — proves the S3 layer.
11. **GitHub Actions CI** — ruff, mypy, pytest on PR.
12. **Migration auto-generation guard** — Alembic `--autogenerate` check in CI to fail PRs that change models without a migration.

## ⚡ Optimizations

- **Replace `declarative_base()` with `class Base(DeclarativeBase): pass`** — SQLAlchemy 2.0 idiom, better typing.
- **`bcrypt.gensalt(rounds=12)`** — default is 12 but be explicit, and consider `argon2` (PHC-recommended).
- **Use a single `httpx.AsyncClient` for outbound calls** (lifespan-managed) instead of per-call clients.
- **Replace `boto3` with `aioboto3`** in [storage.py](../app/core/storage.py#L29) — `boto3` is sync and blocks the event loop on upload/download.
- **Use `orjson` as the default response class** in `FastAPI(default_response_class=ORJSONResponse)` — 3-5x faster serialization.
- **Add `Index` declarations** on common query columns (currently only `email`/`admin_code` are indexed via `unique=True`).
- **Test DB should be Postgres** (testcontainers or a CI service) — UUID column behavior, JSONB, `func.now()` semantics all differ on SQLite and you'll get false greens.

## 🛠️ Small code cleanups

- [app/modules/profile/repositories.py](../app/modules/profile/repositories.py) just delegates to `AdminAuthRepository.get_by_admin_code` — either inline it or give Profile its own logic. As-is it's an empty layer.
- [app/modules/profile/models.py](../app/modules/profile/models.py) is just a comment — delete the file; the registry already handles missing `models.py` gracefully ([registry.py:67-70](../app/core/registry.py#L67-L70)).
- Service "tuple-of-`(data, error_msg)`" pattern is Go-style and easy to misuse (forget to check error, type confusion). Raise domain exceptions and let the (new) handlers map to HTTP — cleaner and less code in routers.
- [tests/conftest.py:38](../tests/conftest.py#L38) `event_loop` fixture is deprecated in pytest-asyncio 0.24+. Use `asyncio_mode = "auto"` (already set) and remove the fixture, or migrate to `event_loop_policy`.
- `Dockerfile` is single-stage and copies code as root. Use a multi-stage build + non-root `USER appuser`. Add `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`.
